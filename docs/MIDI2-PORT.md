goes. Status: **every step done**; L checked on Linux 2026-10-14 (see the handoff below).

The same work was done first in three sibling repos; port from them rather than re-deriving:

- **IFSynth** (`~/Dev-Audio/IFSynth` on the author's Mac; https://github.com/erickampman/IFSynth,
  branch **`master`**): the most recent port, from the same DPF-generated starting point; its
  `docs/MIDI2-PORT.md` is the model for this file.
- **StruckSynth** (`~/Dev-Audio/StruckSynth`; https://github.com/erickampman/StruckSynth, branch
  `main`): also has no VCA (its bank's decay is the envelope) and a fixed Expression panel instead of
  routing dropdowns, so it is the model for item 3.
- **PlainOldSynth** (`~/Dev-Audio/PlainOldSynth`; https://github.com/erickampman/PlainOldSynth,
  branch `main`): where most of it began; its README "MIDI 2.0" section is the reference.

On another machine, clone a sibling next to this repo only when a step needs one; commit hashes in
the table below are in those repos.

All of them vendor the same PolygraphModular engine (`src/Common`, `src/Module`, `src/Voice`).
ModicumFM's `pm_midi.*` and `VoiceStateManager.cpp` are identical to POS's before the port
(`8a3f6be`), so engine commits port nearly file for file: `git show <commit> -- src > x.patch`, then
`git apply --reject x.patch`, and place the rejected hunks by hand.

## ModicumFM as it was (2026-10-14)

- **The CLAP is generated by DPF** (`dpf_add_plugin`), which hands the plugin MIDI 1.0 bytes only:
  no MIDI 2.0, no note ids, no note expressions. Step 0 replaces it.
- **The voice** (`VoiceManager::buildDefaultPatch`): (PitchConverter + PitchBendConverter) →
  Combine 2 (Add) → FM6Op pitch → LPF (filter ADSR on cutoff mod 1, ChannelPressure on mod 2) →
  Chorus (SharedLFO) → Final. **No VCA**: the carriers' envelopes are the amp, and a voice frees once
  Final falls silent. FM6Op reads gate and velocity from the MIDI note-on itself (`fmVelocityLevel`,
  Touch).
- **No modulation routing dropdowns**: pressure is hard-wired to the filter cutoff.
- **Parameters** are appended, never inserted (the host-facing id is the index).

## After the port: the Pitch panel (glide + vibrato, done 2026-10-14)

Agreed with the author on 2026-10-14 (on Linux). First a one-knob **Glide** panel right of
Expression on the Voice tab (`55422f1`); then, since that row had room, it became the **Pitch**
panel: two rows like Expression, captions on the left. Glide (Time, Mode) over Vibrato (Rate, Depth,
Wheel, Sync). 405 px wide at the default size (caption column 60 px); Expression narrows (caption
column 110 px), so both panels' knob cells are ~78 px. Orange, like Global.

- **Glide** `kParamGlide`: seconds per octave, log, **0.001–2 s, default 0.001 = Off** (the knob says
  "Off"). Not IFSynth's 0.0001–2 s: on a log knob that bottom decade was dead travel.
  **Mode** `kParamGlideMode`: Always (default) / Legato. Constant rate (IFSynth's linear Slew).
  Both grey out in Poly (`updateGlideEnabled`; `Dropdown` gained `setEnabled`).
- **Vibrato** `kParamVibRate` (0.5–10 Hz log, default 5), `kParamVibDepth` and `kParamVibWheel`
  (0–100 ct peak, default 0). A second `SharedLFO` (sine; its own phase, since the shared-state
  registry keys on the address; voices-active-only, so it restarts on a new phrase) → a second
  `CCConverter` (CC 1, Per Note off) as a VCA, Offset = Depth/1200 and Amount = Wheel/1200 octaves →
  Combine 2 input 3.
- **Sync** `kParamVibSync`: Shared (default) / Per Note. Not a port of PolygraphModular's per-voice
  `LFOModule` (its phase restarts only on a Reset input's edge, and switching the vibrato between two
  LFO modules would need re-patching or a mixer): `SharedLFO` gained `SharedLFOParamItemPerVoice`
  (appended). On, each voice's copy runs its own phase in `mOmegaL/R` and ignores the shared buffer,
  and `MIDISharedLFOModule` restarts it at note-on unless `Module::legatoHeld` (author's choice,
  2026-10-14: restart at note-on, not free-running). The Clock input is not read per voice.
- Pitch wiring: PitchConverter → **Slew** → Combine 2 input 1; PitchBendConverter on input 2;
  vibrato on input 3. So bend, Pitch 7.25 and vibrato all join after the glide. `applyGlide`
  (plugin.cpp) sends Rise = Fall = Time in Mono above the minimum, else 0.
- `SlewModule` vs IFSynth's: Rise and Fall at or below 0.1 ms pass the input through (Off, and Poly);
  a reset proc + MIDI proc snap the first note-on after init / reset to its pitch (IFSynth's slid up
  from the reference pitch); `SlewParamItemLegatoOnly` (appended) snaps any note-on that is not a
  fingered legato, read from the new `Module::legatoHeld` (the voice was Active, not just releasing,
  as the note-on arrived; set beside `legatoContinuation` in `Voice::handleMIDIMessage`).
- Presets: every preset stores `Global.glide` 0.001, `Global.glideMode` 0 and `Vibrato` {rate 5,
  depth 0, wheel 0, sync 0}, so they sound as before.
- Host tests (`mfm-clap`, "Mono glide" and "Glide mode and vibrato"); the glide ones were
  mutation-checked (removing the snap or the poly gate fails them).
- Found on the way: clap-validator's param fuzz hit subnormal output once the new params shifted its
  (seeded) permutations. Fixed for every module by flushing denormals for the length of `process()`
  (`DenormalGuard`, its own commit). A host test for it did not reproduce the case, so clap-validator
  is the check.
- **Not yet checked in a host** (the panel's look, greying, the wheel from a real controller).

## Working with the author

- Commit to `main` directly, no pull requests; ask before pushing.
- Ask before anything UI-visible: new parameters, panel controls, dropdown entries.
- Before each commit: `ctest --test-dir build` and `clap-validator validate` on the built `.clap`.
- After a rebuild, **quit and restart the host**: a running host keeps the binary it first loaded.
- Synths accept MPE as a compatibility input and never send it.
